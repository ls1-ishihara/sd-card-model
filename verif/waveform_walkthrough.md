# SDカードモデル波形確認メモ

対象: テストベンチ `tb_sd_card_model` が生成した `sd_card_model.vcd`。
[全体波形の画像](sdcardmodel_vcd_1.png)と、CMD17の開始・末尾を拡大して確認した結果をまとめる。拡大画像はチャットへの添付であり、このディレクトリには保存していない。

## 波形を読むときの前提

- VCDの時刻単位は1 ps。`sd_clk`は10 ns周期で、広い範囲を表示するとエッジが塗りつぶされて見える。
- ビューア上のバス値は16進表示。`command_index=37`はCMD55、`29`はACMD41、`11`はCMD17、`18`はCMD24を表す。
- `host_cmd_oe`はテストベンチがCMDを駆動している期間、`sd_cmd_oe`はカードが応答を駆動している期間を示す。`sd_dat0_oe`はカードがデータを送信している期間を示す。
- `sd_cmd`と`sd_dat0`はプルアップ付きのラインなので、Highに見えるだけでは駆動中かHigh-Zかは判断できない。必ず対応する`*_oe`と一緒に見る。
- `command_valid`は48ビットの受信完了を示すパルス。`command_argument`は全コマンド共通の引数で、CMD17の場合に限りSDHC相当のブロック番号として扱う。受理後は`read_block_address`へ保持され、先頭バイトアドレスは`ブロック番号 * 512`となる。

## 初期化とカード選択

リセット解除後、カードはIDLE (`card_state=0`) にいる。CMD0、CMD8の後、CMD55 (`37`) とACMD41 (`29`) の組を3回受信する。ACMD41のReadyは最初の2回が0、3回目が1となり、状態はREADY (`1`) へ進む。次のCMD2でIDENT (`2`)、CMD3でSTANDBY (`3`) へ移る。

CMD7の引数が`9999_0000`のときはRCAが一致せず、R1エラーを返してSTANDBY (`3`) を維持する。次のCMD7の引数`1234_0000`ではRCAが一致し、TRANSFER (`4`) へ移る。この順序は[テストベンチ](../tb/tb_sd_card_model.sv)と[状態管理回路](../rtl/sd_state_manager.sv)の条件に合っている。

## 4回の単一ブロック読み出し

TRANSFER状態でCMD17 (`command_index=11`) を4回発行している。CMD17に対してCMDライン上のR1応答が終わってから8クロック待ち、`sd_dat0_oe`が立ってDAT0送信が始まる。各転送はStart Bitの0、512バイトのデータ、16ビットのDummy CRC (0)、End Bitの1で構成され、計4114クロックの後にDAT0を解放する。CMD17では`card_state=4`を維持する。

| 順序 | `command_argument` | 先頭バイトアドレス | DAT0で送る内容 |
| --- | ---: | ---: | --- |
| 1回目 | 0 | 0 | `boot.mem`の先頭`A5 3C`、以降0 |
| 2回目 | 1 | 512 | 未記載領域のため512バイトの0 |
| 3回目 | 0 | 0 | 1回目と同じ内容を再読み出し |
| 4回目 | 2 | 1024 | イメージ範囲外のため512バイトの0 |

1回目のDAT0開始を拡大すると、最初の1クロックはStart Bitの0。その次の8クロックが`A5 = 1010_0101`、続く8クロックが`3C = 0011_1100`で、いずれもMSB first。「A」と「5」を別々に転送するのではなく、1バイト`A5`をビット順に送る。全体表示ではデータビット・CRC・8クロックの待機は読み取れないため、拡大波形または[自動比較テスト](../tb/tb_sd_card_model.sv)で確認する。

## 4回目の転送後

4回目のDAT0送信終了後、約181.115 usで`sd_dat0_oe`が0に戻る。以降の末尾拡大波形には以下が現れる。

| 時刻 (概数) | 観測と解釈 |
| --- | --- |
| 181.605 us | CMD0受信後、`card_state`がTRANSFER (`4`) からIDLE (`0`) へ戻る。CMD0への応答はない。 |
| 182.085 us | CMD17 (`11`) をIDLEで受信。読み出しは許可されず、状態は0のまま。 |
| 182.115-182.595 us | `sd_cmd_oe`が48クロック立ち、`ILLEGAL_COMMAND`を含むR1を返す。`sd_dat0_oe`は立たない。 |
| 183.075 us | 非対応のCMD24 (`18`) を受信。状態は0のまま。 |
| 183.105-183.585 us | `sd_cmd_oe`が再び48クロック立ち、エラーR1を返す。DAT0の送信はない。 |

したがって末尾の2つの`sd_cmd_oe`の山は、5回目・6回目のデータ転送ではなく異常系に対するCMD応答である。波形の概観・拡大表示とテストベンチのチェックが一致する範囲では期待どおりの動作。ただし全512バイトの値を全体波形の画像だけから判定したものではない。
